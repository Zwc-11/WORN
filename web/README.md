# WORN · web

The consumer-facing frontend (owner A). One screen: pick a hoodie, drag the slider, see the wear owners
photographed drawn on the garment, tap a mark to read their words.

## Run

```bash
npm install
npm run dev            # http://localhost:5173, fixtures
npm test               # frameFor / pinsFor unit tests
npm run check:fixtures # validates public/fixtures/*.json against the zod contract (Node >= 22.6)
npm run build
```

## Flags (`.env`)

| Variable | Values | Effect |
| --- | --- | --- |
| `VITE_SOURCE` | `fixture` (default) · `http` | `FixtureSource` reads `/fixtures/*.json`; `HttpSource` fetches `/api/*` with the same shapes |
| `VITE_API_BASE` | URL | Base for `HttpSource`, e.g. `http://localhost:8787` |
| `VITE_COMPARE` | `0` · `1` | Shows the Compare button and the second stage |

Query flags for the demo and the gate check: `?product=<id>` selects a hoodie; `?state=loading|failed|none|thin`
forces one designed state through `ForcedStateSource` (dev only, not part of the contract).

## Data contract

`src/data/contract.ts` is the Plan v2 contract (`Product`, `Case`, `Dossier`, `Frames`, `DataSource`) with zod
schemas. Two optional additions agreed for P0:

- `Product.image.regions?: Record<Region, {x, y}>` — percent position of each region on the hero image, so
  markers land on the garment. Absent → a generic hoodie map in `DamageMarkers.tsx`.
- When `Dossier.axis` is `null`, `getFrames` returns the product photo only and the slider is replaced by a note.
  `Frames.axis` stays non-null.

Rules the UI keeps: `t` is never filled in; months and washes are never mixed or converted (a case in the other
unit stays off the slider and says so in the drawer); every generated stage is captioned
"Illustration composed from N owner reports"; only counts are shown.

## HttpSource routes (P1, owner B)

```
GET /api/products                 -> Product[]
GET /api/products/:id             -> Product
GET /api/products/:id/dossier     -> Dossier   (404 => evidence 'none')
GET /api/products/:id/frames      -> Frames
```

## Fixtures and stills

`public/fixtures/` holds `products.json`, `<id>.dossier.json`, `<id>.frames.json`. All three hoodies are
**sample data**: quotes start with `[sample]`, source URLs point at example.com, and `dossier.sample` is true.

`public/fixtures/stills/<id>/stage-N.svg` are **placeholder illustrations** generated by
`node scripts/make-stills.mjs`. Replace them with C's lucy-image-2 stills (WebP, 1600 px long side) under the
same paths, or update the paths in `<id>.frames.json`. `sample-photos/` are labelled stand-ins for owner photos.
